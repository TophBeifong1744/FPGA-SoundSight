# 人与大模型协作记录

本项目围绕声音感知、三维声源定位、声纹验证与双轴云台指向控制，构建了一套以 Zynq 异构计算平台为核心、具备触控交互能力的智能声音跟随系统。在项目研发过程中，团队确立了**“人工主导架构与决策、大模型赋能实现与分析、实物实验驱动闭环迭代”**的协作模式。团队始终牢牢把握需求定义、软硬件架构划分、实验方案设计及最终整机验收；同时将繁琐的器件资料检索、样板代码编写、海量运行日志剖析以及自动化脚本开发等工作交由大模型辅助完成，大幅提升了工程推进效率。

### 一、 需求定义与软硬件架构设计

项目初期，团队从实际应用场景出发，明确了系统需解决的四个核心问题：声源空间方向感知、特定目标说话人身份核验、双轴转台实时响应，以及设备端的便捷交互控制。围绕上述目标，团队规划了两种独立且互补的工作模式：**普通声音跟随模式**（根据有效声源方向实时控制云台转向）与**声纹跟随模式**（在完成特定说话人身份核验与权限许可后执行定向跟随）。在这一阶段，团队主导了应用场景界定与系统状态机设计，并借助大模型对模式切换逻辑、边界输入输出条件及潜在异常分支进行完备性梳理，将初步的功能设想快速转化为可量化、可验证的工程技术指标。

在系统总体架构上，团队结合现有 Zynq 开发板资源、外设接口特性及实时性要求，制定了 PL（可编程逻辑）与 PS（处理系统）软硬件协同方案：
* **PL 端**：承担四路麦克风同步采集、底层数字信号预处理、高速数据传输及双轴舵机 PWM 精确控制等强实时性任务；
* **PS 端**：负责三维空间方向解算、声纹特征提取与比对、系统状态管理以及触摸屏 GUI 交互。

团队确定总体技术路线与软硬件划分边界后，利用大模型快速检索器件手册与开发工具文档、核对跨模块接口协议、生成基础驱动框架与构建脚本，有效减少了底层寄存器配置与跨模块联调中的重复性劳动。

### 二、 硬件联调与 FPGA 工程推进

在硬件接入与 FPGA 工程实现阶段，团队负责外围电路连接、电源分配、机械结构装配及板级信号测试，并根据实物运行现象主导故障排查。大模型则根据团队提供的源码片段、引脚约束文件（XDC）、寄存器状态导出值及内核日志，辅助排查接口配置隐患与控制时序问题。

例如，在双轴云台联调初期，曾出现软件端舵机控制指令正常返回、但机械云台无实际动作的现象。团队并未仅凭软件返回值判定驱动正常，而是从指令下发、AXI 总线传输、PL 端 PWM 波形输出到外部供电链路进行了逐级隔离排查；在此过程中，利用大模型快速比对驱动层地址映射与硬件约束配置，最终高效定位并解决了引脚映射与使能控制顺序问题。后续的硬件引脚重分配与外设扩展，均由团队根据实际布线与结构需求作出决策，再借助大模型辅助生成配套的约束修改脚本与测试例程。

### 三、 三维声源定位算法优化与实验迭代

三维定位模块的研发重点在于将理想几何模型与实际麦克风物理阵列精准对齐。团队选定正四面体四麦克风阵列构型，完成物理阵列标定后，组织了涵盖不同方位、距离和发声强度的多组实测实验。针对早期实验中有效定位帧率偏低的问题，团队借助大模型编写了多通道原始音频解析与逐帧日志统计脚本，对有效麦克风对数量不足、方向向量几何约束剔除、历史滑动窗口不连续以及算力瓶颈导致的丢帧等不同诱因进行了定量归因。

在实验推进过程中，团队通过现场观察发现，声源移动速度、发声高度及播放时机的微小波动均会对评估结果产生干扰。为此，团队及时调整实验规范，将测试流程从早期的自由移动发声改进为“固定空间点位、统一高度与音源标准”的受控实验，以严格对比不同算法参数下的表现。团队利用大模型辅助编写了便捷的板端数据采集导出工具与离线仿真对比脚本，在相同真实录音输入下对不同帧长与滤波策略进行批量验证。基于实测数据反馈，团队顺利完成了三维定位前端连续窗口处理逻辑与计算开销的迭代优化，确保了空间方位解算的稳定性与实时性。

### 四、 声纹识别适配与板端推理加速

声纹识别模块的集成由团队明确目标用户注册流程、身份核验规则及权限保持策略，并基于预训练模型开展板端工程化适配。团队负责采集真实环境下的多说话人语音样本，组织目标用户与非目标用户的正负样本对照测试；同时借助大模型快速完成模型推理接口封装、声学特征提取流水线对接以及匹配分数的统计可视化。在联调中遇到持续讲话却未能稳定触发权限许可的异常情况时，团队利用大模型生成的日志诊断工具，对当前激活模板、VAD（语音活动检测）切分结果及余弦相似度分布进行联合排查，从特征对齐与有效语音截取层面根治问题，避免了单纯通过盲目调低判定门限来掩盖系统缺陷。

为进一步缩短声纹核验响应延迟、提升板端交互流畅度，团队主导了针对 PS 端计算瓶颈的多轮性能优化。团队借助大模型快速生成候选优化方案与性能剖析（Profiling）代码，重点围绕以下四个方面展开攻关：
1. 音频采集缓冲区的数据校验开销精简；
2. 运行时内存分配与缓存复用策略优化；
3. 针对固定输入维度的模型算子裁剪与固化；
4. VAD 与声纹特征提取模型的流水线协同加速。

在每一轮优化迭代中，团队均采用控制变量法，在相同测试集输入下严格比对优化前后的数值一致性与端到端实际耗时，并以实板整机联调的实时响应表现作为最终取舍依据，实现了算法精度与板端算力开销的最佳平衡。

### 五、 触摸屏交互演进与整机系统集成

在多模块向总工程集成的过程中，团队各成员按算法优化、系统守护进程、底层硬件驱动与整机测试进行模块化分工。为保障协作效率，团队利用大模型辅助规范化模块间 API 接口定义、整理构建脚本与自动化测试入口，确保各子模块在板端集成时具备清晰的接口契约与可追溯的测试记录。

触摸屏交互子系统的开发充分体现了团队工程经验对技术路线的决定性作用。为摆脱对上位机串口终端的依赖，团队提出引入触摸屏作为独立人机交互终端，并结合团队过往积累的硬件工程经验进行移植。初次接入时，实板出现 GUI 界面短暂显示后因触摸芯片通信异常而崩溃退出的故障。团队在利用大模型辅助分析内核 I2C 报错日志、尝试软件重试机制无果后，果断结合既往成功经验改变底层硬件链路方案，决定将触摸控制器改由 PS 端 I2C0 经 EMIO 路由接入。随后，团队借助大模型快速完成 Vivado 硬件配置更新、设备树（Device Tree）节点重构及应用层设备访问路径调整，最终在实板上实现了稳定、低延迟的触控响应，彻底消除了异常黑屏现象。

在交互功能完善阶段，团队紧扣实际使用体验，规划了清晰的模式切换界面、目标用户选择、运行参数配置、系统启停控制及实时状态监控面板，并借助大模型高效完成了 GUI 事件回调与底层业务守护进程的通信对接。随着工程向产品化形态演进，团队进一步设计并实现了开机服务自启动、触屏端声纹实时录入、工作模式断电保持以及安全确认关机等完整闭环功能，使系统从最初依赖命令行调试的实验原型，全面演进为可独立开机运行与交互的完整智能硬件设备。

### 六、 整机测试验收与工程规范化

系统的测试规划与最终验收标准始终由团队严格把关。团队紧密围绕比赛技术指标与实际应用场景，设计了声纹许可超时后的非目标说话人抗干扰测试、多方位三维声源动态转向测试、触控界面高负荷连续操作测试等综合验收用例。测试过程中，大模型主要辅助编写自动化日志解析脚本与Vivado时序/资源报告提取脚本（TCL），帮助团队从“进程状态正常”“方向解算有效”“舵机物理响应到位”“身份核验准确”等多个维度进行量化评估与交叉核验，确保软硬件各项指标均在实板上得到扎实验证。

### 总结

纵观整个项目研发历程，团队与大模型的协作并非简单的“单向指令输出与结果照搬”，而是构建了**“人工定义问题与边界—大模型辅助编码与分析—实物实验检验—人工决策修正”**的紧密工程闭环。大模型充分发挥了在跨领域知识检索、样板代码生成、多方案快速对比及海量日志统计方面的高效工具价值；而团队则牢牢把控了系统架构设计、关键技术路线取舍、软硬件实物联调、实验科学设计以及最终整机验收等核心环节。正是通过这种优势互补的深度协作，团队得以在有限周期内高效攻克多项软硬件协同难题，圆满完成了从核心算法验证到可交互整机系统的工程化落地。
