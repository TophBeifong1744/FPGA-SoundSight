# 连续采集与异步处理

用于DMA采集同时运行推理、显示、记录或执行器控制的系统。参数与行为取实际接口合同。

## 调度、持久性与缓存

采集任务在FIFO预算内取包、处理缓存并续接。平均耗时小不代表最坏间隔合格；分别记录poll gap、rearm、解码/拷贝、推理和写盘的分布/最大值。

逐帧fsync可能阻塞采集。按产品需求选择有界RAM队列后批量落盘，或仅保留统计/故障。高水位留出停止在途数据的余量。RAM接受、硬件CONSUME、持久化是不同事件；断电丢失边界必须明确，不能默默降低原持久性要求。

异步推理可保留最新待处理任务，正在执行的任务不半途覆盖。显示用有界最新状态，串口阻塞不反压采集。分进程、绑核不等于实时调度保证，仍看实测间隔与积压。

连续音频/传感数据与定位/显示快照分别设策略。快照drop不自动等于采样丢包，也不能被省略。锁帧不覆盖。序号缺口如何影响窗口由算法合同定义，不能一概重置或忽略。

## 评分、许可与动作

对具有分类评分和执行器的系统，评分、带期限许可和动作分别记录。动作受实际控制合同限制，例如定位应用的方向/音量、机械限位、STOP和硬件租约；无执行器系统不要求添加这些接口。

采用成功评分刷新TTL时，明确失败评分、静音、旧来源、新会话、换目标的行为及TTL起算点。延长TTL不是推理加速。近期N条结果不能算全程通过次数、均值和最大值，需显式累计。

存在手动标定时，可与算法输入独立，但保留限位、超时和停止。不同授权策略分别验收；例如声音跟随与身份许可跟随不能混为一个通过结论。提交次数不是机械到位次数。

## 环境与排障

分辨Python/驱动导入、Overlay匹配、时钟复位、数据与算法后再决定硬件动作。sudo环境可能不同；实际参考时钟来自板级配置，不能仅信API默认值。UI显示不替代原日志与寄存器事实。

整机重启与程序异常分开。保存启动/运行原件，核对供电、负载及接线；仅凭重启不能认定某个原因。接线、供电、下载和复位按任务授权执行。
