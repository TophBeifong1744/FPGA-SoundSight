# 四麦PCM接入设计

当前完整硬件采用S2配方，工程入口见[根目录说明](../../README.md)，部署见[板端安装说明](../../board/guides/public-deployment.md)。下文保存PCM数据通路和寄存器设计。

## 接入内容

- 复用现有四麦PDM/CIC；将原16深度PCM跨域通路扩展为98位标记流。每512点插入一次时间标记，PCM本身仍为96位，加必要标志；不逐样本携带64位编号，也不增加第二套采集跨域逻辑。
- 在100MHz域分出2048组四麦PCM缓存和小型块描述队列，使用官方XPM。每512组完整采样发布一个包；录音使用连续PCM数据流。
- 新增 `audio_capture`、仅S2MM的 `axi_dma_audio`、1入1出的 `audio_mem_bus`；原控制互联改为1入3出。DMA流宽32位，内存侧及HP0为64位，Simple模式、16位长度字段，关闭MM2S/SG/Micro/DRE。
- PCM通路及DMA使用现有100MHz；PDM和主采样计数仍在61.44MHz域。只在需要处跨域，复用原时钟及复位架构。
- 保留原IRQ位0；DMA接IRQ位1，其余14位为0。原寄存器地址 `0x40000000` 保留；DMA为 `0x40400000`，音频控制为 `0x43C00000`。
- 定位窗记录原采样起点，元数据经过原特征输出槽、跨域和快照双槽同步保存。窗口编号、特征发布编号和快照编号各有用途，不能相互冒充。取消帧及BIST的真实音频关联无效。
- 时间扩展由 `AUDIO_ENABLE` 控制，默认0。旧SPI字段、S1数值算法和既有手动/声音动作保护不变。

主要文件：`ss_pcm_time_cdc.sv`、`ss_audio_fifo.sv`、`ss_audio_capture.sv`、`bd_audio_capture.v`，以及既有compute包装、分窗、特征保存、快照与PS寄存器模块。完整更新文件清单就在统一Tcl的 `names` 中。

## v1包与寄存器

每包8224字节：8个32位小端包头字＋512×4个32位PCM字。PCM按 `mic0,mic1,mic2,mic3` 交错，有符号24位右对齐并符号扩展，不移位、不截断。固定48kHz，块长不在运行时修改。

| 字偏移 | 内容 |
|---|---|
| 0 | `0x43505353`，内存字节为SSPC |
| 1 | 高16位头长32字节，低16位格式版本1 |
| 2 | 32位capture_epoch |
| 3 | 32位block_seq，从0开始 |
| 4/5 | sample_start低/高32位 |
| 6 | 高16位flags，低16位sample_count=512；flags bit0为本块削顶，其他位0 |
| 7 | PCM载荷8192字节 |

在原采集run_enable下，首个预热完成的有效采样编号为0，每个四麦采样递增一次；暂停或丢样不能通过DMA握手速度改变这个时基。停止再启动必须使用新会话。PS计算排他终点，不在PL重复存终点。

音频控制偏移：

| 地址 | 内容 |
|---|---|
| 0x00 | `0x00010001`，v1及四麦原始音频能力 |
| 0x04 | 写1准备新会话，写2停止新增音频，写4锁存采样进度；读bit0 armed、bit1已见run |
| 0x08 | 待启动epoch，仅空闲时可写，非0且不得等于上一会话 |
| 0x0c | bit0 armed，bit1有完整包等待/发送，bit2有不完整尾部，bit3可重新配置，bit4 DMA复位已释放，bit5采集准备好；[15:8]错误 |
| 0x10/14 | 48000Hz / `0x04201801`：4通道、32位容器、24位有效、交错小端 |
| 0x18/1c | 512点/8224字节 |
| 0x20 | 首次拒收事件计数，不是全部丢失采样数 |
| 0x24 | 已封存完整块数 |
| 0x28/2c | 显式快照的采样进度低/高32位，不是活动计数器拼读 |
| 0x30 | 本次实际会话epoch |

错误位0～5依次为FIFO/描述队列满、块起点不符、块序号耗尽、采集源故障、非法控制访问、DMA复位中断。错误及尾部状态必须连同录音保存，不能只看最后一个完整包就判断整次无缺口。

PS原寄存器区扩展：0x80能力版本，0x84锁帧epoch，0x88/8c锁帧首采样低/高位，0x90源窗口编号，0x94低16位窗口长度1024、bit16关联有效。必须先按原协议锁帧，读取全部字段后再消费；普通总线复位仍保留原锁帧，但软件必须废弃旧会话关联。

## 软件接入顺序与停止

本次交付工程入口，不在脚本中执行板端接收。后续接收程序须：撤动作许可并停原采集、消费并排空旧快照；准备对齐的8224字节DMA接收缓冲；写新epoch及ARM，等待音频状态bit5；提交DMA接收，再开启原采集run。录音过程中持续消费原定位快照，避免旧队列满导致原定位路径故障。推理不占用接收服务。

音频STOP只停止音频分支新增，完整包继续排空，不自动停止原定位链。整机STOP仍走原停用/撤许可入口；检测到run下降后音频也结束。停止或故障造成的不完整尾部不发布为正常包，通过状态报告，下一会话准备时清除。缓冲拥塞采用明确失败并停止本次录音，不自动跳过后继续伪装连续；先处理故障并建立新会话。

DMA复位输出连接音频模块，取消在途包并清除传输队列；软件必须等DMA确实停止写内存后才能释放缓冲。冷复位、总线复位或PS进程重启后，软件使用新会话并丢弃旧音频/推理引用，不能只依赖硬件“不同于上一次”检查防止所有历史编号复用。

Simple DMA需要软件逐块续接。FIFO只能吸收有限调度抖动，尚未证明PYNQ持续录音不丢样。第一步板测须检查实际包长、四通道声音、采样连续性、定位时间关联及停止；声纹与转向接入留到这些检查完成后。
